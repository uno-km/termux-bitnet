Advanced Parameters & Tuning

Kernel-level tuning, buffer pool sizing, and thread configuration

1. 1.58-Bit Ternary Kernel Vectorization

Traditional floating-point neural network inference relies heavily on Multiply-Accumulate (MAC) operations. BitNet 1.58-bit constrains weights to the ternary set:

W ∈ {-1, 0, +1}^{m × n}

Matrix multiplication $Y = W \cdot X$ is converted into vectorized additions and subtractions of activation vectors. The ARM64 NEON Dot-Product engine executes these operations via vdotq_s32 instructions, maximizing throughput while minimizing transistor switching energy.

2. Memory Footprint & Android LMK Defense

Android OS executes the Low Memory Killer (LMK) when free system memory falls below critical thresholds (typically 300MB ~ 500MB). Termux-BitNet protects against LMK aborts via:

  • Zero-Copy Memory Mapping (mmap): Model weights remain mapped directly from disk into read-only virtual address space, sharing pages with the OS cache.
  • Pre-Allocated KV Cache Ring Buffers: Prevents continuous heap allocation and fragmentation during autoregressive generation.
  • Sub-350MB Peak Working Set: Operates safely within low-RAM mobile devices (Galaxy A-series, S-series).

3. KV Cache Context Memory Formulation

Context window memory allocation is strictly bounded by the formula:

KV_Cache_Bytes = 2 × n_layers × n_heads × d_head × n_ctx × 2 (FP16)

For BitNet 2B with $n_{\text{ctx}} = 2048$, KV Cache consumes approximately 128MB, ensuring lightweight on-device execution.
